# System prompt — spec-side source of truth

This directory is the **spec-side source of truth** for the applessOS system
prompt. It closes the prompt half of the Phase 0 exit criterion
(docs/NATIVE_MIGRATION_PLAN.md §9): the prompt assembled from these sources is
**byte-identical** to the `SYSTEM_PROMPT` export the RN app ships in
`src/genos/generated/system-prompt.ts` — `check-prompt.mjs` enforces it in CI
(`.github/workflows/spec-gates.yml`). Native ports (Swift/Kotlin) must embed
the assembled prompt from here, not re-derive it from the web repo.

```
spec/prompt/
├── build-prompt.mjs             assembles the prompt → system-prompt.generated.txt
├── check-prompt.mjs             byte-compares vs src/genos/generated/system-prompt.ts
├── system-prompt.generated.txt  the assembled prompt (committed artifact)
└── sections/                    stored-verbatim pieces (see below)
    ├── preamble.txt
    ├── component-signatures.txt
    ├── additional-rules.txt
    └── examples/example-{1..4}.txt
```

## Rebuild / verify

```bash
cd spec/fixtures/generator && npm install   # once — build-prompt reuses its esbuild loader
node spec/prompt/build-prompt.mjs           # writes system-prompt.generated.txt
node spec/prompt/check-prompt.mjs           # exit 0 iff byte-identical to the shipped prompt
```

## What is GENERATED vs what is STORED

The shipped prompt was originally produced by the appless-os **web** repo
calling `library.prompt(...)` (`@openuidev/lang-core`'s `generatePrompt()`)
and then adapted by `scripts/embed-prompt.mjs`. `build-prompt.mjs` replays
that pipeline against **this repo's** real contract:

**Generated** — by calling `library.prompt({preamble, examples,
additionalRules})` on the real library built from `src/genos/ui/contract.tsx`
(same esbuild loader as the fixture generator, `@openuidev/lang-core` 0.1.2):

- `## Syntax Rules` (rule set and numbering derive from the library's
  feature flags: no tools, no bindings, `ActionExpression` present)
- `## Action - Button Behavior`
- `## Hoisting & Streaming (CRITICAL)`
- `## Examples` framing (heading + blank-line joins around the stored bodies)
- `## Important Rules` + `## Final Verification` (verification list derives
  from the same flags)
- the `- `-bullet framing of the additional rules
- overall section ordering and inter-section spacing

**Stored verbatim** (in `sections/`) — prompt content that does not live in
any code contract in this repo, plus one section that genuinely cannot be
regenerated byte-identically today:

- `preamble.txt` — the applessOS persona paragraphs (authored prose).
- `examples/example-{1..4}.txt` — the four few-shot example bodies
  (authored prose/code).
- `additional-rules.txt` — the 21 appless-specific rules, one per line
  (authored prose; `generatePrompt` adds the `- ` prefixes).
- `component-signatures.txt` — the **entire `## Component Signatures`
  section, including its 3 header lines and group notes**. Honesty note:
  this section SHOULD be generated from `contract.tsx`, and `build-prompt.mjs`
  still generates a candidate for it — but then splices this stored file over
  it, because byte-identical generation is not achievable with the pinned
  `@openuidev/lang-core` 0.1.2:
  - its signature builder predates the one the web repo used for the shipped
    prompt: it cannot annotate `$binding<...>` props or optional props whose
    zod type is `.nullable()`/unions (it emits `subtitle` where the shipped
    prompt has `subtitle?: string`, drops `rules?: {...}` object annotations,
    and consequently also omits the `$binding` header line);
  - it renders props in contract (zod-shape) order — `labels, series, xLabel,
    yLabel, variant` — while the shipped prompt lists `variant` third for the
    cartesian charts;
  - several component descriptions/notes in `contract.tsx` have drifted from
    the shipped prompt's wording (ListItem "get a chevron" vs "show a
    navigation affordance", Bubbles/Tabs iOS-specific phrasing, the extra
    "Chart values must be non-negative" Stats & Charts note).

  When the contract or lang-core's prompt builder is upgraded to close these
  gaps, delete the splice in `build-prompt.mjs` and this file, and the section
  becomes fully generated.

**Adaptations** — after assembly, `build-prompt.mjs` applies exactly the
transformations `scripts/embed-prompt.mjs` applies when embedding
(`" | CheckBoxGroup | RadioGroup"` removal, em/en-dash → hyphen
normalization, `trimEnd`), so the spec-side build and the app-side embed
agree byte-for-byte.

## Changing the prompt

1. Edit the stored section files here (or `contract.tsx` + lang-core for the
   generated parts).
2. `node spec/prompt/build-prompt.mjs`.
3. Re-embed into the app: `npm run generate:prompt -- spec/prompt/system-prompt.generated.txt`
   (from the repo root — `scripts/embed-prompt.mjs` accepts an explicit path).
4. `node spec/prompt/check-prompt.mjs` must pass. Note the shipped
   `system-prompt.ts` is what the app sends the model; the app additionally
   appends a `Today is <date>` line and (when configured) a web-search tools
   section at runtime — those are runtime concerns, outside this spec.
